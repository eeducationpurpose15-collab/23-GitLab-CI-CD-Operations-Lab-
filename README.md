# GitLab CI/CD Operations Lab — автоматизация сборки и тестирования проекта

## Цель проекта

**организовать проект в Git, развернуть GitLab и GitLab Runner и настроить автоматизированное выполнение проверок проекта**.

Самостоятельно подготовить виртуальную машину, развернуть GitLab и GitLab Runner, создать учебный Git-проект и организовать выполнение автоматизированных заданий через Runner.

Затем настроить автоматический QA и статический анализ безопасности SAST и проверить прохождение полного автоматизированного процесса.

Рабочая программа непосредственно предусматривает П.З.1 «Git. Организация проекта», П.З.2 «Развёртывание GitLab и GitLab Runner на виртуальной машине» и П.З.5 «Автоматический QA». 

**Исходные условия:** у преподавателя и студентов нет готового GitLab, GitLab Runner или учебного проекта. Необходимый стенд создаётся с нуля по ходу выполнения проекта.

**Формат реализации:** GitLab и GitLab Runner развёртываются на виртуальной машине в соответствии с П.З.2 рабочей программы. 

**Порядок обучения:**

**виртуальная машина → Git → GitLab → GitLab Runner → CI/CD → автоматический QA → SAST → итоговая проверка.**

# Этапы выполнения

## 1. 🟢 Подготовить виртуальную машину

**Дано:** необходимо подготовить среду, на которой будут размещены GitLab и GitLab Runner.

**Задача:** подготовить работающую виртуальную машину.

**Решение:**

1. Создать виртуальную машину.
2. Запустить её.
3. Проверить доступ к виртуальной машине.
4. Проверить готовность системы к установке необходимого программного обеспечения.

**Результат:** виртуальная машина работает и доступна для дальнейшей настройки.

**Проверка:** подключение к виртуальной машине выполняется успешно.

**Соответствие программе:** П.З.2 — «Развёртывание GitLab и GitLab Runner на виртуальной машине». 

---

## 2. 🟢 Организовать проект в Git

**Дано:** виртуальная машина подготовлена, но учебный проект и его репозиторий отсутствуют.

**Задача:** организовать учебный проект с использованием Git.

**Решение:**

1. Создать каталог учебного проекта.
2. Создать несколько файлов проекта.
3. Инициализировать Git-репозиторий.
4. Добавить созданные файлы.
5. Зафиксировать изменения.
6. Проверить историю изменений.

**Результат:** создан учебный Git-проект с сохранённой историей изменений.

**Проверка:** Git показывает созданный репозиторий и выполненную фиксацию изменений.

**Соответствие программе:** П.З.1 — «Git. Организация проекта». 

---

## 3. 🟢 Развернуть GitLab

**Дано:** учебный проект организован в Git, но централизованная платформа для размещения проекта отсутствует.

**Задача:** развернуть GitLab на виртуальной машине.

**Решение:**

1. Установить GitLab.
2. Выполнить первоначальную настройку.
3. Запустить GitLab.
4. Создать учебный проект в GitLab.
5. Разместить созданный ранее Git-репозиторий в GitLab.

**Результат:** GitLab работает, а учебный проект размещён в нём.

**Проверка:** интерфейс GitLab доступен, репозиторий и его файлы отображаются.

**Соответствие программе:** П.З.2 — «Развёртывание GitLab и GitLab Runner на виртуальной машине». 

---

## 4. 🟢 Развернуть GitLab Runner

**Дано:** GitLab работает, но отсутствует исполнитель автоматизированных заданий.

**Задача:** развернуть и подключить GitLab Runner.

**Решение:**

1. Установить GitLab Runner.
2. Зарегистрировать Runner в GitLab.
3. Связать Runner с учебным проектом.
4. Проверить состояние Runner.

**Результат:** GitLab Runner зарегистрирован и готов выполнять задания проекта.

**Проверка:** подключённый Runner отображается в GitLab и доступен для выполнения заданий.

**Соответствие программе:** П.З.2. 

---

## 5. 🟡 Настроить CI/CD

**Дано:** GitLab и GitLab Runner работают, но задания проекта ещё не выполняются автоматически.

**Задача:** организовать автоматизированное выполнение задания проекта.

**Решение:**

1. Создать конфигурацию CI/CD для учебного проекта.
2. Добавить простое автоматизированное задание.
3. Сохранить конфигурацию в репозитории.
4. Запустить задание.
5. Проверить выполнение задания через GitLab Runner.
6. Изучить результат выполнения.

**Результат:** GitLab автоматически передаёт задание Runner, а Runner выполняет его.

**Проверка:** автоматизированное задание имеет успешный статус.

**Соответствие программе:** лекция 1.2 — «Платформы непрерывной интеграции и доставки». 

---

## 6. 🟡 Настроить автоматический QA

**Дано:** автоматизированное выполнение заданий настроено, но автоматическая проверка проекта отсутствует.

**Задача:** добавить автоматический QA.

**Решение:**

1. Подготовить автоматизированную проверку учебного проекта.
2. Добавить проверку в автоматизированный процесс.
3. Запустить её через GitLab Runner.
4. Просмотреть результат проверки.
5. Убедиться, что результат автоматически фиксируется.

**Результат:** автоматический QA выполняется без ручного запуска проверки.

**Проверка:** GitLab показывает результат автоматизированной проверки.

**Соответствие программе:** П.З.5 — «Автоматический QA». 

---

## 7. 🟠 Выполнить SAST

**Дано:** автоматический QA настроен, но статический анализ безопасности проекта ещё не выполняется.

**Задача:** провести SAST учебного проекта.

**Решение:**

1. Подготовить средство статического анализа.
2. Настроить анализ учебного проекта.
3. Запустить SAST.
4. Получить результаты анализа.
5. Изучить обнаруженные замечания.

**Результат:** выполнен статический анализ безопасности и получены результаты проверки.

**Проверка:** результат SAST доступен для анализа.

**Соответствие программе:** лекция 2.5 — «Автоматизированный QA. SAST. DAST» и Л.Р.2 — «SAST».  

---

## 8. 🟠 Проверить полный автоматизированный процесс

**Дано:** Git, GitLab, GitLab Runner, CI/CD, автоматический QA и SAST настроены.

**Задача:** проверить совместную работу всех созданных в рамках проекта компонентов.

**Решение:**

1. Внести изменение в учебный проект.
2. Зафиксировать изменение в Git.
3. Передать изменение в GitLab.
4. Запустить автоматизированный процесс.
5. Проверить выполнение задания через GitLab Runner.
6. Проверить результат автоматического QA.
7. Проверить результат SAST.
8. Зафиксировать итоговый результат.

Полный учебный процесс:

**изменение проекта → Git → GitLab → CI/CD → GitLab Runner → автоматический QA → SAST → результат.**

**Результат:** изменение проекта проходит полный автоматизированный процесс, а результаты проверок доступны в GitLab.

**Проверка:** все предусмотренные этапы выполняются последовательно и завершаются получением результатов.
